# site-ai-reposition — 需求分析

> 一句话：把 mdocs-site 的**产品叙事与信息架构**从「轻量知识库五件套」升级为 **AI 原生知识库**（产品内上手 Agent + 外部 Agent 开发闭环），并与 mdocs / mdocs-cli 已落地能力对齐；**不编造未交付功能**。

## 背景

- 首页 Hero 标签与特性区仍主推：`零依赖部署` / `双模编辑` / `无账户协作` / `智能草稿` / `Agent Ready`。
- `Agent Ready` 仅一句「CLI + Claude Code 读写知识库」，**没有**讲清：
  1. 产品内 **上手助手（AI）**（答疑不代写、读本站手册、Session 落盘）；
  2. **mdocs-cli Skills**（`mdocs-cli` / `mdocs-dev` / `diagram`）把 mdocs 接入 Agent **开发流程**。
- 手册里已有 [`docs/docs/usage/onboarding-ai.md`](../../docs/docs/usage/onboarding-ai.md)，但首页、侧栏权重、竞品页叙事仍像「2025 初版知识库」，严重落后于产品方向。

## 目标

1. **首页第一眼**让人读出：mdocs = 可被 AI 使用、也被 AI 辅助使用的私有知识库（不只是 Markdown + SQLite）。
2. **拆清两条 AI 路径**（避免混成一句空话「Agent Ready」）：
   | 路径 | 谁用 | 已落地依据 |
   |------|------|------------|
   | **产品内上手 Agent** | 访客在 Web 里问「怎么用」 | mdocs `onboarding-ai`；本站手册为 Skill 真源 |
   | **外部 Coding Agent 闭环** | Cursor / Claude 等经 CLI + Skills 搜读写知识库、落开发契约 | mdocs-cli；mdocs-dev / diagram |
3. **旧能力降级为底座**（仍真实、仍要写，但不再占 Hero 主位）：零依赖、双模编辑、无账户、草稿。
4. **文档 IA**：侧栏 / 文档首页突出 AI 与 Agent 相关章节；必要时新增「给 Agent / 开发者」入口页。
5. 文案与能力边界一致：**不暗示**代写、润色、选区改文档（上手 Agent 明确非目标）。

## 非目标（本期不做）

- 改 mdocs / mdocs-cli 产品代码或发版流程
- 新做站点交互重设计（动效、全新视觉体系）——只改叙事、结构、必要文案与示意图说明
- 宣称未交付能力（写作 Agent、UI 高亮引导、多模型厂商等）
- 重写全部 changelog / 竞品对比到字；可局部补 AI 相关段

## 验收标准

1. Hero 主标签或副文案中，**至少两条**直接对应「上手 AI」与「Agent 开发闭环」，不再以旧五标签原样为主。
2. `#features` 区块中，AI 相关模块排在**前两屏可见**（或明确第一节），且两条路径分节可辨。
3. `rspress` 侧栏与 `docs/docs/index.md` 能在 ≤2 次点击到达上手助手与 CLI/Agent 说明。
4. `/docs/why-mdocs` 与首页特性叙事一致（同一套卖点，不双标）。
5. 全文无「帮你写文档 / 自动改正文」类误导承诺；上手助手仍强调答疑边界。
